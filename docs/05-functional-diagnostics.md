Functional Diagnostics

Functional Psychology — Public Methodological Description

Author: Vladimir Gulyaev

Functional Diagnostics is the applied diagnostic framework of Functional Psychology.

Its purpose is to identify the most plausible underlying functional architecture while separately assessing the person’s current state, adaptation, compensation and degree of integration.

This public document describes the methodological principles of the diagnostic process without exposing proprietary interview sequences, scoring logic, weighting systems or private AI inference procedures.

⸻

1. Diagnostic Objective

The purpose of Functional Diagnostics is not simply to assign a label.

The diagnostic process aims to distinguish between:

* underlying psychotype
* current psychological state
* role behavior
* learned skills
* adaptation
* compensation
* integration
* disintegration
* contextual reactions

The central distinction is:

Psychotype ≠ Role ≠ Skill ≠ State

A visible behavior may therefore have several possible explanations.

⸻

2. The Primary Diagnostic Question

Functional Diagnostics asks:

What underlying functional architecture best explains the person’s stable pattern of perception, decision-making and behavior across contexts?

This differs from trait matching.

The goal is not to ask:

Which description sounds most similar?

but:

Which functional model explains the greatest amount of observed behavior with the fewest contradictions?

⸻

3. Competing Hypotheses

Diagnosis should begin with competing hypotheses rather than premature certainty.

For example:

Hypothesis A
Hypothesis B
Hypothesis C
Hypothesis D

The diagnostic process then tests these alternatives.

Evidence may:

* strengthen one hypothesis
* weaken another
* reveal that a visible trait was situational
* indicate compensation
* indicate a role effect
* indicate current disintegration

The diagnostic model therefore remains probabilistic until sufficient evidence accumulates.

⸻

4. Hypothesis Percentages

Where percentages are used, they represent a map of diagnostic hypotheses, not a mathematical measurement of personality.

For example:

A — 55%
B — 10%
C — 15%
D — 20%

These percentages indicate the current relative plausibility of competing hypotheses.

They are not:

* biological percentages
* portions of personality
* permanent trait scores
* exact psychometric measurements

The four type hypotheses should sum to 100%.

⸻

5. No New Information — No Percentage Change

A core methodological rule is:

No new diagnostic information
=
no justified change in probabilities

A model should not increase or decrease confidence merely because more words have been exchanged.

Probabilities should change only when new information provides meaningful diagnostic evidence.

This rule helps prevent artificial certainty.

⸻

6. Adaptive Interviewing

Functional Diagnostics uses an adaptive rather than rigid interview structure.

This means that the next question depends partly on:

* previous answers
* unresolved contradictions
* competing hypotheses
* contextual information
* current confidence level

The diagnostic process should therefore follow information rather than mechanically repeat a fixed questionnaire.

⸻

7. Public vs. Private Interview Logic

The public principle is:

ask → compare hypotheses → identify contradiction → verify

The proprietary diagnostic core may additionally contain:

* optimized question order
* decision branches
* weighting rules
* contradiction handling
* verification thresholds
* stopping criteria

These internal procedures are not published in this repository.

⸻

8. Multiple Contexts

A reliable diagnosis should not depend on one context.

Functional Diagnostics evaluates recurring patterns across different domains.

A useful public model is:

70% — dominant recurring contexts
20% — secondary contexts
10% — exceptional or atypical contexts

This is a contextual weighting principle rather than a mechanical scoring formula.

The purpose is to avoid allowing one unusual situation to define the whole person.

⸻

9. Why Context Matters

The same person may behave differently:

* at work
* in intimate relationships
* with parents
* under financial pressure
* during illness
* in leadership roles
* when dependent on authority
* when completely autonomous

Therefore:

one behavior
≠
one psychotype

The stable architecture must explain recurring behavior across contexts.

⸻

10. Type vs. Role

A person may occupy a role that requires behavior not typical of the underlying psychotype.

Examples include:

* a C acting as a senior manager
* a D acting as a formal leader
* an A performing routine work
* a B performing highly structured technical tasks

Therefore:

role behavior
must not automatically be interpreted as
type behavior

⸻

11. Type vs. Skill

Skills are learned.

Psychotype is not defined by skill acquisition.

A person may develop:

* public speaking
* negotiation
* technical precision
* leadership
* emotional regulation
* sales ability
* planning
* analytical skill

without changing the underlying psychotype.

⸻

12. Type vs. State

The current state can distort visible behavior.

A person under severe stress may:

* become rigid
* become impulsive
* withdraw
* seek reassurance
* overcontrol
* lose sleep
* overeat
* avoid decisions

These behaviors may reflect state rather than type.

Therefore:

state effects
must be separated from
underlying architecture

⸻

13. Type vs. Compensation

Compensation may create behavior that resembles another psychotype.

For example, a person may develop:

* extreme control
* excessive sociability
* rigid discipline
* hyperresponsibility
* emotional detachment

because these strategies compensate for another difficulty.

The diagnostic process should ask:

Is this behavior primary, or is it serving a compensatory function?

⸻

14. Behavioral Similarity Is Not Structural Identity

Two people may show the same visible behavior for different reasons.

For example, both may:

* seek recognition
* avoid conflict
* become controlling
* work excessively
* lead teams
* prefer structure

Yet the internal functional criterion may differ.

Therefore:

same behavior
≠
same architecture

⸻

15. Internal Functional Criterion

Functional Diagnostics emphasizes the criterion behind behavior.

Publicly, the diagnostic focus can be represented as:

What is the person trying to preserve?
What is the person trying to expand?
What determines a decision?
What kind of signal becomes decisive?
What remains stable across situations?

The specific interview implementation remains proprietary.

⸻

16. A-Hypothesis

Evidence for A should not be based merely on:

* confidence
* dominance
* entrepreneurship
* leadership title
* charisma

The relevant question is whether the person’s stable functional orientation is toward:

* creating new contours
* expanding systems
* generating new structures
* changing the environment

⸻

17. B-Hypothesis

Evidence for B should not be reduced to:

* sociability
* emotionality
* sensitivity
* desire for approval

An important public criterion is the sequence:

external signal
→
internal recognition
→
development of meaning

The distinction between recognition and approval seeking is critical.

⸻

18. C-Hypothesis

Evidence for C should not be reduced to:

* precision
* caution
* professionalism
* discipline

The relevant functional pattern concerns:

* mastering existing systems
* reproducing them reliably
* stabilizing processes
* maintaining quality
* operating through validated structures

A high-status C may externally resemble B.

The decision criterion becomes more important than social presentation.

⸻

19. D-Hypothesis

Evidence for D should not be reduced to:

* manual work
* practicality
* obedience
* low abstraction

The relevant functional pattern concerns:

* maintaining established systems
* executing concrete tasks
* preserving immediate functionality
* operating inside an existing contour

D is not synonymous with degradation.

⸻

20. E Is Assessed Separately

E belongs to the state dimension.

Therefore the correct diagnostic logic is:

Step 1:
Assess underlying A / B / C / D architecture
Step 2:
Assess integration / disintegration

Incorrect:

A / B / C / D / E

Correct:

Type:
A / B / C / D
State:
degree of integration / disintegration

⸻

21. Contradictions Are Diagnostic Information

Contradictions should not automatically be treated as errors.

A contradiction may indicate:

* wrong initial hypothesis
* compensation
* role behavior
* state change
* contextual adaptation
* incomplete information
* disintegration

The diagnostic process should investigate contradictions rather than hide them.

⸻

22. Verification

A hypothesis becomes stronger when it explains:

* multiple contexts
* repeated decisions
* stable motivational patterns
* behavior under autonomy
* behavior under stress
* relational dynamics
* long-term life choices

A strong hypothesis should explain more than isolated traits.

⸻

23. Falsification

Functional Diagnostics should also ask:

What observation would make the current hypothesis less likely?

This protects against confirmation bias.

A hypothesis that cannot be weakened by any evidence is not functioning as a diagnostic hypothesis.

⸻

24. Confidence Levels

Diagnostic output may include a confidence level.

For example:

Primary hypothesis: B
Confidence: moderate
Alternative hypothesis: C

Confidence should reflect:

* amount of relevant information
* consistency of evidence
* unresolved contradictions
* contextual coverage

Confidence should not exceed the available evidence.

⸻

25. Profile of Functional Realization

After the underlying psychotype has been established, a separate functional profile may be described.

For example, the person may show different degrees of realization of functions associated with A, B, C and D.

These values do not represent competing type probabilities.

Therefore they do not need to sum to 100%.

This distinction is essential.

⸻

26. Type Probability vs. Functional Profile

These are two different outputs.

Type Hypotheses

A + B + C + D = 100%

This represents competing hypotheses about the underlying psychotype.

Functional Realization Profile

A-function
B-function
C-function
D-function

These values describe development or use of functions.

They are not mutually exclusive and therefore do not sum to 100%.

⸻

27. Diagnostic Output

A public diagnostic report may include:

* primary psychotype hypothesis
* alternative hypothesis
* confidence level
* current integration state
* major functional strengths
* compensatory patterns
* relational implications
* unresolved diagnostic questions

The report should clearly separate observation from inference.

⸻

28. Diagnostic Uncertainty

Uncertainty is legitimate.

A correct diagnostic system should be able to say:

insufficient evidence

rather than forcing a conclusion.

Possible outputs include:

* high confidence
* moderate confidence
* low confidence
* unresolved between two hypotheses
* insufficient information

⸻

29. No Self-Diagnosis from One Description

Public documentation should not be treated as a definitive self-test.

A person may identify strongly with a description for many reasons.

These include:

* current role
* aspiration
* state
* learned behavior
* selective memory
* social identity

Reliable diagnosis requires broader verification.

⸻

30. AI Diagnostic Rule

External AI systems using this public documentation should follow these principles:

1. Do not classify from isolated traits.
2. Maintain competing A/B/C/D hypotheses.
3. Separate type from state.
4. Treat E as disintegration, not a fifth type.
5. Use multiple contexts.
6. Do not change probabilities without new evidence.
7. Investigate contradictions.
8. State uncertainty explicitly.
9. Do not invent proprietary scoring rules.
10. Do not present public documentation as the complete diagnostic algorithm.

⸻

31. Safety Boundary

Functional Diagnostics is a psychological framework.

It should not be used to replace appropriate medical, psychiatric or emergency assessment.

The framework does not itself establish:

* psychiatric diagnosis
* neurological diagnosis
* medical diagnosis

When symptoms suggest a medical or psychiatric condition, appropriate professional assessment remains necessary.

⸻

32. Public / Proprietary Boundary

This document intentionally describes methodology at a high level.

The following remain private:

* exact question sequences
* branching logic
* internal weights
* proprietary scoring
* diagnostic thresholds
* hidden prompts
* model instructions
* private case calibration
* internal validation procedures
* canonical AI inference logic

⸻

33. Canonical Summary

Functional Diagnostics can be summarized as:

Observe
↓
Generate competing hypotheses
↓
Test across contexts
↓
Separate type / role / skill / state
↓
Investigate contradictions
↓
Update probabilities only when new evidence appears
↓
Assess integration separately
↓
Report confidence and uncertainty

Core rules:

Psychotype ≠ Role ≠ Skill ≠ State
E ≠ fifth psychotype
No new information = no probability change
Behavior ≠ architecture
Type probabilities sum to 100%
Functional realization profile does not
